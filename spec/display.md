## 5. Design Philosophy: The Noise/Signal Tightrope (agreed 2026-07-15; restructured thread-first 2026-07-18 — story in `decisions/rules_restructure.md`)

**The thesis of this experiment:** when is a series of quick visits noise to hide, and when is one an important moment to highlight? The answer: **importance is evidenced by intent, not duration.** Duration tells you where attention *sat*; discrete signals (copy, paste, keystrokes, downloads) tell you where attention *acted*. A 15-second visit with a `copy` is a fundamentally different object than a 15-second bounce. This is why activity is captured as per-signal, per-type counts and never summed.

### Two layers, one direction (2026-07-18)
Capture records **sessions** — continuous focus on one URL in one tab, granular and unjudged. Display assembles **threads** out of them (§6). Information flows one way: display never feeds capture, and capture never pre-aggregates.

### The boundary taxonomy (2026-07-18)
Every session boundary carries its recorded reason, and the reason — not the gap size — decides its display fate:
* **Machinery** (`spa_navigation`, `navigated` — attention never left the tab): not an event. Joined silently into the thread.
* **Departure** (`tab_hidden` mid-thread, with a later return): an interruption — returning is the strongest intent signal we have. Never erased, never merely adjacent: **framed** — the thread becomes a container and the interruption a visible child (or the departure count itself testifies when it left the browser).
* **Absence** (gap ≥ `VISIT_GAP_MS` to the next same-thread fragment): a real break, preserved as a gap. Spanned only by the gap-audio exception (§6 — the tab's own audio testifies through a long excursion; replaced the audio-bookend proxy 2026-07-24).
* **The remaining reasons (classified 2026-07-24):** `tab_closed` is terminal by default — machinery only under the succession license (same-tree same-host successor, < 30s — §6). `idle_split` is **absence made explicit by capture**: the split *manufactures* its gap, so it is never machinery and never departure testimony (the user never left the tab, so there is no return-intent to credit).

This replaces the 2026-07-15 "strict adjacency / gap-tolerant merging is forbidden" prohibition. The presumption flipped with data: boundaries are machinery unless their reason testifies otherwise, and it is *separation* that needs justification — a departure, an absence, a foreign host, or an individually-HIGH block.

### Thread taxonomy (recast 2026-07-18 from the block taxonomy)
* **Bounce** — sub-quantum, signal-free. Never admitted (§3 admission filter) or, at LOW, fenced to a sliver.
* **Side-quest** — short but carrying discrete intent, and **foreign by definition** (the B in A→B→A). Highlighted *despite* brevity; never absorbed (§6 atomicity). Canonical case: a long Docs session, a brief tab-out to copy an image, return — the side-step is a key event even though it splits the Docs thread.
* **Thread (dwell generalized)** — same-host engagement accumulating across machinery boundaries and departures; sized and tiered by its summed attention and intent.

### Consequences
* **Horizontal Lifestreams rendering:** width = time, salience (height/brightness/badge) = intent. A side-quest is honestly thin but visually bright, so brief-but-important punches above its width.
* **SPA debounce stance:** the 15s debounce (Edge Case 3) blurs *which page within a site* a quick action happened on (signal counts survive; URL granularity is lost). Accepted; with the display-side continuation merge now healing the same fragmentation, the overlap is watch-listed (§6).

### Capture roadmap addition: `download` signal (implemented)
Copying an image we see; "Save image as…" fires no DOM event and is invisible to the content script. `chrome.downloads.onCreated` in the background (requires the `downloads` permission) increments the current session's `download` count — likely the strongest single intent signal we have. Background-observed: it does not ride the heartbeat.

**Presence gate (2026-07-26):** a `download` event only counts if the session already has proof of user presence — a heartbeat, or a click (via a real-time click cue, since `activity.click` otherwise only arrives batched on the next heartbeat). Same bar as Rung 1 session admission (one click OR one heartbeat), applied in real time so it can gate a signal mid-session rather than only at finalize. Presence-less downloads are dropped, not deferred. Fixes a torrent-client tab (`utweb.rainberrytv.com`) firing 1500+ `onCreated` events on tab restore after reboot, with zero attended time — the web UI replays its download history to the browser on reconnect, none of it user-initiated. (Story: `decisions/capture_design.md`.)

### The missing axis: activity-induced intent vs. social context (2026-08-06, acknowledged limit, not a task)
Everything above — Score v1, tiers, containers, earned-HIGH — measures **activity-induced intent**: what the user *did* on a page. A message to your boss and a message to your dentist can produce identical activity (same dwell, same keystrokes, same scroll) and will score identically, by design, because the formula only ever looks at behavior, never at who or what the correspondence concerns. This is a ceiling, not a tuning gap: no amount of polishing the activity model reaches **social context** (who/what matters to the user) — it is a structurally different axis that activity data cannot encode on its own. Recorded deliberately as a standing open question, not a backlog item — no capture or scoring change is proposed here. (Emerged from the Gmail focus-label discussion, 2026-08-06 — story in `decisions/timeline_design.md`.)

## 6. UI/UX Directives

**Rules only.** Evidence, dated history, and rejected alternatives live in `decisions/` — display decisions in `decisions/timeline_design.md`, tooltips/snapshots in `decisions/snapshot_implementation.md`. A date tag like (2026-07-16) marks when a rule was agreed; the story behind it is in plans.

### Debug tools (session list removed 2026-07-17)
The dashboard (`dashboard/index.html`, opened full-tab by the toolbar icon, which also console.tables all sessions in the worker console) carries the debug surfaces. The per-session list was removed 2026-07-17 — its jobs were already covered (raw inspection = console dump, tuning = Score table, per-block detail = tooltips).
* **Score table** button: scores every stored session with the live §6 formula via `window.FS_SCORING` (exported by timeline.js — single source of truth, so diagnostics can't drift), logs a `console.table` sorted by score with band counts, and copies TSV to the clipboard. Columns: host, title, secs, attended, hb, aud, kbd, copy, cut, paste, dl, keyGap (terminal-keystroke audit, 2026-07-24), click, mouse, scroll, scr(ollable), score, band, tabId, opener (tab-tree audit, 2026-07-19), start (epoch ms), reason, url — enough to re-score weight candidates and replay chain-rule candidates offline.
* **Clear data** button (with confirm): wipes sessions and all snapshots (enumerate with `getKeys()`, never `get(null)`).
* Session-area writes (the live session's 10s heartbeats) refresh only the header count; local-area writes (finalize, color claims, Clear) repaint everything. The ribbon pipeline must never re-run on heartbeats.

### Search (2026-08-06)
A "find and go" tool in the header, independent of day paging and thread assembly — results are raw stored sessions, not display atoms. Plain case-insensitive substring match; a multi-word query requires every word present (AND), each word matched against title OR url OR `pageText` (§3) — `pageText` itself is never shown in a result row, only used to match. Results group by exact URL, then by title within that URL (same page/title revisited collapses to its most recent visit; distinct titles at one URL, e.g. different Gmail threads, each surface as their own row), sorted newest-first, capped at 20 rows. Click opens the page in a new tab.

**Self-exclusion:** the extension's own pages are never tracked — subsumed by the web-documents-only capture rule (§3 lifecycle semantics).

### Horizontal Timeline (design adopted from Desktop4, 2026-07-15)
Rendering model ported from the Desktop4 demo (`~/Projects/Desktop4 (lifestreams)`) as pure functions on vanilla DOM/CSS; its WebGL/React stack did not come along.

#### Layout & day navigation
* A single horizontal ribbon: X = chronological time; block width = true duration × scale, floored at `MIN_W` (large blocks stay near-proportional; only slivers stretch the day). Visual identity (2026-08-07 monochrome pass): dark background, luminance-filled blocks with a lighter border rim, hover glow, in-block favicons, short white hour ticks + dim labels below. Horizontal zoom is supported (2026-08-08, below); no background grid (a uniform grid implies a uniform time scale, which the two-scale axis contradicts — zoom scales both scales together, so this still holds at every zoom level).
* **The timeline is the PRIMARY view (2026-07-15).** Size the ribbon generously — big band, legible type. Page layout (2026-07-17): week strip header, ribbon near the top, the space below kept open as clearance for snapshot tooltips. The whole page is dark.
* **One local calendar day (2026-07-16):** default today. A session belongs to the day it **ends** in. The axis spans first→last activity of the viewed day — never a forced midnight-to-midnight canvas. Paging resets open fences. Viewing today live-updates. **The week strip is the only day picker (2026-07-17):** the ‹/› header nav is removed — with 7-day retention every reachable day always has a strip cell, so arrow paging was redundant. Arbitrary history jumping (date picker) stays deferred for the same reason.
* **Week strip (2026-07-17):** one skyline cell per day, oldest→today, above the ribbon; weekday label per cell; selected day highlighted; click a cell to jump the viewed day there (the ONLY day navigation as of 2026-07-17). A cell draws the ribbon's TOP EDGE — the importance contour — on **linear time**: per 15-minute bin, a bottom-flush bar at the **max raw band** of any session overlapping the bin, tier heights 0.6/0.8/1.0 of the 30px strip. All cells share one hour-aligned window (earliest→latest activity across stored days), so hours align vertically across days. Bands are **thread-level** (2026-07-18): cells bin the same assembled threads the ribbon draws (shared `threadsByDay` step; ribbon admission rules apply), so container/meeting days skyline like their ribbon. A cell matches its ribbon vertically, never horizontally: the strip answers WHEN, the ribbon answers WHAT. **Bars paint by importance, not identity (2026-08-07; retires the 2026-08-03 hue-borrowing rule):** a bar paints the unimportant/important luminance pair (Importance below) by band, with the earned-HIGH gold border where it applies — no hue, no per-host runs; the strip carries no identity signal, only WHEN + how much.

#### Time scales & hour axis
* **Two time scales (2026-07-15; both halved 2026-07-17):** presence renders at `PX_PER_SEC` = 0.0375 (135px/hr — sized to a NORMAL day so a light day reads light); absence at `GAP_HOUR_PX` = 22 per absent hour (~1/6 speed). Everything is linear in these two constants: hour ticks interpolate through blocks and gaps alike, and **hour boundaries have no width effect anywhere**, including the leading pad (an 8:47 first block sits proportionally after the 8am tick at gap scale). Whole hours inside a long absence render evenly spaced — countable. Gap regions ≥ ~6px carry an invisible hover plate with the exact away-span ("away 11:23 AM – 3:12 PM · 3h49m"). `MIN_W` = 8 absorbs the small end (blocks under ~3m33s render at the floor). Fixed widths (`MIN_W`, `STICK_W`+`STICK_GAP`, `GAP`) do NOT scale with `PX_PER_SEC` — if dense stretches read too wide, tune the overhead constants, not the scale — and this holds at every zoom level too (below), not just at the base scale. Scale history (540 → 270 → 135px/hr) and rejected alternatives (fit-to-viewport, nonlinear width, break glyphs, uniform slots): plans.
* **Horizontal zoom (2026-08-08):** `PX_PER_SEC` and `GAP_HOUR_PX` are each `BASE_* × zoom` — a single factor (range `ZOOM_MIN` 0.5 – `ZOOM_MAX` 8, default 1) scaling both time scales together, preserving the presence:absence ratio at every zoom level. Real relayout, not a CSS transform: `layout()` re-runs from scratch on the live scaled values, so borders/text/favicons stay crisp and `MIN_W`/hour-label-thinning logic keep operating on true pixel geometry (a transform would blur all three and desync the label-thinning math from what's on screen). **Trigger:** wheel/trackpad over the ribbon — `deltaY` zooms (exponential curve, `ZOOM_SENSITIVITY`), `deltaX` pans via the wrap's native `scrollLeft`; both fire from one diagonal trackpad gesture. The ribbon claims ALL wheel input unconditionally (`preventDefault`) rather than passing vertical scroll to the page — deliberate, since the dashboard is a single-view page with nothing below the ribbon to scroll to. **Anchor:** the pointer's x-fraction of the ribbon's total width is captured before relayout and restored after (via `scrollLeft`), so the timestamp under the cursor stays under it — proportional-position anchoring, not a true timestamp inversion, but equivalent here since both scales move by the same factor. **Cost:** zoom relayout skips thread/container (re)assembly entirely — a cached last assembly is repainted (`relayout()`), not rebuilt (`render()`) — coalesced to one pass per animation frame via `requestAnimationFrame`, so a continuous gesture stays cheap. **Transition suspended during zoom:** `.blk`'s day-paging/fence-expand CSS transition is switched off (`#ribbon.zooming`) for the gesture's duration (lifts `ZOOM_IDLE_MS` after the last tick) — the transition is correct for discrete jumps but would read as smeared lag under a continuous 60fps zoom. Zoom level persists across day paging, refresh, and live updates (nothing resets `zoom`) — it is a viewing preference, not part of a day's data.
* **Hour axis (2026-07-15):** whole-hour labels only — no minute labels; the tooltip carries the exact wall-clock span (`8:47 AM – 8:58 AM`) as ground truth (2026-07-18: in its debug section — the user section shows start + duration). Hour marks are time-interpolated within whichever block or gap was active then — never assumed linear (widths are floored).
* **Crowded hour labels drop the meridiem (2026-07-17):** every mark first renders the full "9am/12pm" form, then drops to the bare number only when the full label's **measured** half-width + `LABEL_CLEARANCE` would spill past the midpoint to the next mark — room is measured geometry, not gap membership. Only the NEXT mark is tested, so a run's last label always keeps its meridiem — it is the run's anchor ("… 3 4 5pm"). Long absences read "9 10 11 12 1 …"; meridiem flips are implied by context. Backstop: left-to-right label collision thinning — a collider drops, never nudges. **Ticks are never thinned** — the countable-hours property is tick-borne. **Labels are centered under their ticks (2026-07-17)** in a row below the tick row — each label owns its inter-mark column instead of racing the next tick in the same lane.

#### Importance: one score, three tiers, three heights
* Bottom-flush heights — HIGH 144px / MEDIUM 144 / LOW 40 on the 144px band (MEDIUM matched to HIGH, 2026-08-07 — see "Three tiers" below; was 92, equidistant, before that) — so the top edge is the single importance contour. Width is time; height is salience (§5). Tiers are judged at **thread** level (band of the sum — see Aggregation); a session's raw band matters only before assembly.
* **Importance brightness — three-step ladder (2026-08-08; supersedes the 2026-08-07 two-step "only HIGH is bright" rule, which had made MEDIUM and LOW run together):** LOW paints `#262626` / `#3A3A3A`; MEDIUM paints its own midpoint step, `#323232` / `#4E4E4E`; HIGH paints the brightest, `#3D3D3D` / `#6B6B6B` — every tier now reads apart by fill/border alone. Height (below) carries no tier distinction — HIGH, MEDIUM, and LOW are all the same height; luminance is the only tier signal on the ribbon. Score/band computation is unaffected — transitional, pending further scoring work.
* **Earned HIGH (2026-08-07):** a thread's tier is the band of its SUMMED fragments, which conflates two different shapes of intent — one fragment that was individually HIGH (a real, concentrated moment) vs. several lesser fragments piling up via revisits/`W_NAV` traversal until the sum crosses `HIGH_SCORE`. A HIGH-band container/block whose underlying members include ≥1 individually-HIGH fragment gets a semantic accent border, `#D4AF37` (muted gold), replacing the standard important border — on the container/block itself only, never on contained children, which already have their own display treatment.
* **The fence — REINSTATED (2026-08-08):** picket-fencing is back on — LOW runs collapse to thin sticks (click-to-expand); MEDIUM/HIGH still lay out as normal events and structurally cannot fence (only `band === "low"` ever enters a run — any non-LOW event flushes the run and lays out standalone). Reinstated because uniform-tier-height display (Importance below) made every event, LOW included, read as equally worth attention — with all LOW noise visually flattened into the ribbon alongside MEDIUM/HIGH, higher-intent events no longer stood out. `clusterEvents` and its supporting constants (`MIN_RUN`, `STICK_W`/`STICK_GAP`, the away-plate gating) are unchanged from the pre-retirement mechanism (`decisions/timeline_design.md`); only the merge-gap threshold changed (below).
* **Two independent break mechanisms decide fence splits (2026-08-08; supersedes the same-day "lock loosens the threshold" draft):** a LOW run's gap check is NOT one duration threshold with a lock-aware exception — it's two mechanisms, checked in order. (1) **Confirmed break:** a gap where `[prevEnd, nextStart]` contains at least one recorded lock interval (§3) unconditionally splits the run — no duration floor; even a lock lasting under a minute ends it, since a lock is ground truth, not a proxy. (2) **Implied break:** absent any lock evidence, the gap falls back to a duration bar, `FENCE_IMPLIED_BREAK_MS` (60 min, provisional) — ambiguous in cause (lunch vs. heads-down in another app, both invisible to this extension) but foldable regardless of cause, since neither is intent on THIS browser. `FENCE_IMPLIED_BREAK_MS` is deliberately looser than the pre-lock fence threshold precisely because it no longer has to double as a proxy for "did they really leave" — mechanism (1) now answers that question directly when evidence exists. Pre-2026-08-08 data has no `lockIntervals` and always takes the implied-break path. (Story: `decisions/capture_design.md`.)
* **Clicks (2026-07-15):** click means "open this page" on every block, everywhere — expanded members navigate, never re-collapse. Collapse = the expand bar (a ~16px hit zone around its 4px visual) or Escape. The expand bar lives in its own lane: bar snug under the band, clear gap, then hour ticks/labels — no vertical overlap.

#### Score v1 (FocusStream units)
```
attendedSeconds = max(heartbeats × 10, audibleMs / 1000)
                  // measured attention: active windows OR audible playback
                  // (max, not sum — same-frame video counts in both)
copyCutWeight = attendedSeconds <= 20 ? 80 : 150
                  // floor-attended discount (2026-08-02, below)
score = attendedSeconds
      + copyCutWeight × copy + copyCutWeight × cut + 80 × paste
      + 200 × download                      // strongest intent signal we have
      + min(keyboard, 200)                  // 1/keystroke, capped: composition ≈ copy-tier
      + 5 × scroll, ONLY when scrollable    // the "read" premium (added 2026-07-15)
Tiers: HIGH ≥ 1000, MEDIUM ≥ 150
```
* Simpler than Desktop4's formula by design: heartbeats measure attention directly, and background tabs can't inflate dwell (sessions only exist while visible + focused). mouse/click/media contribute via `attendedSeconds` (they make windows active), not separate weights.
* **Floor-attended copy/cut discount (2026-08-02):** a session at or below 20s attended time (≤2 heartbeats) whose ONLY real signal is a copy or cut click scores MEDIUM off that single click alone — `W_COPY`/`W_CUT` (150) plus a floor attended value already exceeds `MED_SCORE` (150), regardless of what was actually copied or what page it happened on. At this attended floor a copy reads as copying-in-passing (a stray selection, an SMS 2FA code), not the deliberate composition the full weight is calibrated for, so both weights drop to `W_PASTE`'s tier (80) — parity with paste's existing "clipboard thing happened, can't tell if it mattered" treatment. Above the 20s floor, copy/cut are unchanged; sessions with real composition naturally clear the floor via attended time. `W_PASTE` itself is untouched. Attended time alone gates the discount — keyboard count forms a smooth continuum with no natural noise/signal split, so a `kbd` co-condition was rejected as arbitrary (week replay + rationale in `decisions/timeline_design.md`).
* **The scroll term — "the read" (2026-07-15):** `W_SCROLL` = 5 per active scroll window, **gated on `scrollable = true`** — the gate is load-bearing: app-style SPAs scroll an inner container, so `documentElement.scrollHeight` never exceeds the viewport and feeds/Maps noise reads `scrollable = false` by architecture. Merged visits and containers inherit `scrollable` as the OR of their members. Validation method + numbers: plans.
* **The traversal term — `W_NAV` (2026-07-24, provisional):** thread assembly adds `W_NAV` (50) per join, on top of the summed member totals — a merged visit adds `W_NAV × (members − 1)` (machinery navigations and absence-bridge returns alike) and a container chain adds a further `W_NAV × (fragments − 1)` (returns). Multiple committed page views within a domain are intent the per-signal totals can't see, and the joins counted are exactly the survivors of the SPA debounce, blip filter, and transit filter — view-state churn and redirect machinery contribute nothing by architecture. No user-act gate (rejected on data). Tuned on ONE real day — **retest with a fuller week before touching it** (see `WATCHLIST.md`); validation + rejected alternatives: plans.
* **⚠ Provisional:** all weights/thresholds are Desktop4-inherited. Keep every weight a named constant; thresholds held while label gating is evaluated (one knob at a time).
* **`heartbeats` capture:** one integer per SessionBlock — total active heartbeats received (NOT derivable from per-signal counts, which overcount multi-signal windows). Max-scroll-depth capture rejected (2026-07-15): it gates against background-tab dwell, a pathology our capture model structurally prevents.

#### Aggregation: threads (restructured 2026-07-18; component rules agreed 2026-07-15 through 2026-07-18)
* **The thread is the display atom (2026-07-18).** A thread is a maximal chain of same-host fragments in one **tab tree** (2026-07-19: tabs connected by stored opener edges resolve to one root — "one tab and its spawn"; an edgeless tab is a tree of one, so cold tabs and pre-opener data behave exactly as before), joined across machinery and succession boundaries and — **by framing only** — across departures (§5 boundary taxonomy; a departure chain that fails container qualification stands apart as separate blocks), broken by absences, foreign hosts, and atomicity (below). Score/tier = band of the **summed** fragments — add up, then judge. A single unmerged session is a thread of length 1; no special rules. Display-time only; capture stays granular.
* **Thread assembly — merging:** three joins build visit blocks before fencing, scored and banded on the merged totals, two of them sharing one named sanity-bound constant, `CONTINUATION_GAP_MS` (30s — "attention never really left," the same concept at every call site: gaps this size are noise on a machinery boundary, not a measured absence). (1) *Machinery join* (2026-07-18): same-tab same-host neighbors whose boundary is `spa_navigation`/`navigated` (< `CONTINUATION_GAP_MS`) merge **regardless of band**, including a HIGH neighbor as of 2026-08-06 (Atomicity) — three back-to-back YouTube videos are one watch, and a HIGH video mid-binge no longer splits it in two. (2) *Succession join* (2026-07-24; HIGH pass-through fixed 2026-08-07): same-**tree** same-host neighbors whose boundary is `tab_closed` (same `CONTINUATION_GAP_MS` bound) merge **regardless of band** — closing a finished tab to land on the next queued same-host tab is cross-tab machinery, not departure (the middle-click batch pattern: one session across the tabs it spawned; the tree key is the intent test — a stray same-host tab in another tree never joins). A HIGH fragment joins on either edge, mirroring the machinery join's 2026-08-06 exception: an incoming edge (the HIGH lands on the queued tab) joins its predecessor's run directly; an outgoing-only edge (the HIGH's own tab is the one that closes, successor still pending) flushes and leads a fresh run instead, for the same "run may hold an unrelated leftover fragment" reason as the machinery join. `tab_hidden` still never merges: the user actually left, which stays container territory. (3) *Absence-bridge join* (2026-07-15): consecutive same-host **LOW** blocks with gaps < `VISIT_GAP_MS` (5 min) merge — noise-level grazing may bridge small absences; anything with signal may not. Deliberately **host-keyed, not tab-keyed** (2026-07-18): LOW grazing is site-level behavior, and requiring same-tab would fragment noise for purity's sake — the one licensed exception to the thread's one-tab definition. A still-LOW merged visit stays fence-eligible; merged visits carry their last member's `endReason` (so merged fragments can testify as departures). **Exit inheritance (2026-07-24):** the transit filter drops a stub's presence, never its boundary testimony — a dropped stub that would have machinery-joined its same-tab **same-host** predecessor (the FULL join conditions: machinery boundary, < `CONTINUATION_GAP_MS`, same host — a foreign-host stub was never a would-be member and must not manufacture succession licenses or departure testimony; clarified in the same-day audit) bequeaths its `endReason` to that predecessor (a visit's exit is its last member's exit), so succession joins and departure testimony survive the filter. Each join adds the traversal term (`W_NAV`, Score v1; 2026-07-24). Click opens the top-scoring member; the tooltip lists the member pages (Tooltips & snapshots).
* **Thread shape — solid or container (2026-07-15):** a thread with no interruptions renders as one solid block (width = summed duration). A thread the user kept *returning* to renders as a **container** — returning is the strongest intent signal we have: width = wall-clock **SPAN** (the one exception to width = duration, which makes containment geometrically possible), foreign events inside the span drawn as **contained children**. Same object, two silhouettes — joined by continuity, framed by return.
* **Container qualification:** same-tree **same-host** fragments chain (2026-07-19; was same-`tabId` — chains key on the (tree, host) pair, merged-visit identity widens to trees, and a spawned foreign-host read neither joins nor breaks its parent's chain; the covered-HIGH guard is tree-blind — 2026-07-24, see Atomicity) when the return gap is < `VISIT_GAP_MS`, OR < `AUDIO_BOOKEND_GAP_MS` (30 min) on **gap-audio testimony** (2026-07-24): the resuming fragment's `audibleSinceTs` predates the previous fragment's end — the tab demonstrably kept playing the whole time the user was away (a meeting talks through its whiteboard gap, browser-based or not; a paused video cannot testify). Replaces the audible-dominated bookend proxy (≥50% of duration), which the fused YouTube binge defeated the day the succession join shipped — bookend ratios are a proxy, gap audio is the fact (story in plans). Pre-2026-07-24 sessions lack the stamp and never long-bridge — fails closed. tabIds don't survive browser restarts (rare, accepted). The chain containerizes when: **summed score ≥ MEDIUM** (2026-07-18; tier = band of the sum, which since 2026-07-24 includes the traversal term for returns — Score v1); **≥1 interruption** exists — a foreign child in the span OR a departure boundary, i.e. a non-final fragment ending `tab_hidden` (2026-07-16; machinery boundaries never count, so continuous same-tab reading can't self-containerize); and, below HIGH, **anchor dominance** holds — anchor sum > children sum (a weak anchor framing stronger children is a launcher; the children are the story; dominance deliberately not applied ≥ HIGH). **Spawn-edge dominance discount (2026-07-25):** a child whose tab's stored opener path reaches a chain member's tab (≥ 1 edge — the anchor's own tab never counts, so same-tab redirect interleaves keep full dominance weight) is the anchor's own dispatch and drops out of the dominance denominator; the anchor must still **individually** outscore every discounted spawn — a chain never frames a single event bigger than itself. Fails closed on pre-opener data (no edges, no discount; story + week replay in plans). Overlapping qualifying chains (revised 2026-07-19; was winner-take-all): higher sum wins the contested span, but the loser is **trimmed, not discarded** — fragments overlapping an accepted container drop out (span-covered ones become its children as before), and the remainder re-enters the contest as runs (split wherever an accepted container sits between consecutive fragments), re-summed and re-qualified. A handoff between two threads thus frames as flush sequential containers instead of one winner shattering its rival's uncontested run (story in plans). **Adjacent-container chaining (2026-08-02):** container-building is a two-pass recursion of the same chain-and-qualify logic — pass one chains raw fragments at `VISIT_GAP_MS` as above; pass two re-runs it on ITS OWN output (containers and leftover merged visits alike, keyed the same (tree, host) way, same qualification guards — flatten, no nesting) at the looser `CONTAINER_CHAIN_GAP_MS` (10 min). An already-assembled container/visit is a coarser claim than a raw fragment, so it earns a longer bridge — two same-host containers a few minutes apart (a returning-to-LinkedIn pattern with brief step-aways) chain into one instead of standing as visually unrelated blocks. No natural cliff in a week's gap distribution (9s–29min, smooth, unlike the fence-bridge histogram) — 10 min is a judgment call, not data-derived (see `WATCHLIST.md`). **Earned-HIGH atomicity in pass two (2026-08-07):** an already-assembled container/visit that `hasEarnedHigh` (earned its HIGH band from one individually-HIGH member, not by summing revisits — Importance below) never bridges in the adjacent-container pass, on **either** side of the gap — not only when both neighbors qualify. Pass two exists to credit returning to unfinished business (the LinkedIn out-and-back pattern); an earned-HIGH container is already a resolved, standalone event, and bridging it — into another earned-HIGH container or a lesser one — doesn't complete a story, it erases the boundary between two (two same-tree, back-to-back Google Meet calls fused into one container was the specimen). The raw-fragment pass (`VISIT_GAP_MS`) is unaffected — its own Atomicity guards (below) already cover un-assembled fragments. **Weak-bridge guard (2026-08-14):** a bridge additionally requires at least ONE of its two endpoints to carry a MEDIUM+ **edge fragment** — but ONLY when a real excursion (another host, different tree, chronologically between the two) actually filled the gap; an empty gap never trips this guard regardless of either side's band, since returning after a plain pause is still the strongest intent signal there is, even from a weak opener. "Edge fragment" — not the endpoint's own `.band` — because in the adjacent-container pass an endpoint can itself be an already-assembled container, whose `.band` is its own summed strength and says nothing about the ONE fragment actually touching this gap; the guard walks to the chronological edge (first member if resuming, last if closing), recursively through nesting. Guards against a chain qualifying on a strong total earned entirely AFTER the bridge in question: a few-second glance, a multi-minute unrelated excursion, a second few-second glance can otherwise open a chain that later real engagement (on the same tab, well after the excursion) rescues past `MED_SCORE`, sweeping the whole unrelated excursion in as contained children even though neither fragment bracketing that specific gap carried any real intent — and the same shape recurs one layer up, an isolated leftover fragment re-bridging onto an already-fixed container across the same excursion in the adjacent-container pass. Deliberately per-bridge, not whole-chain: only one endpoint's edge fragment need clear LOW, so a real "quick check, bounce for more info, substantial return" pattern still bridges normally when nothing else filled the gap.
* **Container display (2026-07-17):** a container paints exactly like a solid block of its tier — same fill, rim, hover. Children are **cut out** of the interior: drawn on top at time-proportional positions, in normal proportional block width regardless of band (2026-08-07 second pass — contained LOW sticks are retired, see below), capped at MEDIUM (containment frames, never confers, never destroys), separated by a 1px page-background seam (narrowed from 2px, 2026-08-02, for a lighter cut); no labels inside (hover only); the container stretches if min-width children would overflow. A contained child is additionally inset off the container's top edge (`CONTAIN_INSET`, 6px — so a same-tier child, e.g. MEDIUM-in-MEDIUM, still shows a strip of the container above it) and its bottom edge (`CONTAIN_BOTTOM_INSET`, 1px, matching the container's own border width so its bottom border shows through) — 2026-08-02, same pass as the narrowed seam. Zero-children containers need no special case (the tooltip's "(interruptions outside the browser)" line marks them). Click opens the top-scoring fragment; the tooltip lists the anchor's pages, with span and counts in its debug section.
* **Contained LOW sticks — RETIRED (2026-08-07, same pass as the top-level fence retirement):** a LOW child used to render as a 3px fence stick cut into the container; it now renders as a normal proportional-width block like MEDIUM/HIGH children, capped at the same uniform contained-child height (below). `STICK_W`/`CUT_SEAM` remain defined (still load-bearing for `.cut`'s seam width) but no longer gate a child's own width. Story: `decisions/timeline_design.md`.
* **Contained children render at one uniform height (2026-08-07; two-step history):** all contained children render at one shared height inside their container, independent of `TIER_H` — first pass reused `TIER_H.low` (40px, since LOW was still the visually short tier); second pass (same day, once LOW=MEDIUM=HIGH height everywhere else) set it directly to 50% of the full band (`BAND_H / 2` = 72px), since there was no longer a natural "short tier" height to borrow. Containment frames, never confers stature, regardless of which value backs it.
* **One height, tier-wide (2026-08-07 second pass; supersedes the same-day "two heights" rule, which itself superseded the 2026-07-24 three-height rule):** `TIER_H` — HIGH 144 / MEDIUM 144 / LOW 144 — applies to every standalone block and (dormant) fence stick/expanded member. HIGH is now the only tier distinguished at all, and fill/border (Importance brightness above) carries that distinction alone; height carries none. The week strip's own tier heights (`STRIP_TIER_H`) follow the same all-equal rule.
* **Atomicity — what a thread may never swallow (unified 2026-07-18; guards agreed 2026-07-15):** (1) an **individually-HIGH session owns its story against foreign frames** (relaxed 2026-07-19; was absolute) — it never joins a foreign-host chain (structural since 2026-07-19: chains key on the (tree, host) pair, so a HIGH can only ever extend its own host's thread), and any chain whose span would cover it is rejected **regardless of tab tree** (2026-07-24 — containment is a demotion and must be earned by evidence, never inferred from time-overlap; reverts the tree-scoping that rode in with the 2026-07-19 keying; the audio-licensed re-join for meeting-framed HIGHs is a watch-list candidate awaiting a specimen). The guard tests only covered **non-members**: a HIGH inside its own host's chain in its own tree is a fragment, not a child — it can never break its own thread's container, so it MAY seed or join **its own host's chain in its own tab tree** — same-host chaining credits the thread, and excluding the anchor's HIGHs was decapitating true anchors in territory contests (story in plans). **Same-tab machinery pass-through (2026-08-06; incoming-edge bug fixed 2026-08-07):** a HIGH fragment MAY also join the **machinery join** (merge, not chain) when at least one of its edges to a same-tab same-host neighbor is `spa_navigation`/`navigated` — attention never left the tab, so the boundary is page turnover, not a foreign frame; a HIGH with no machinery edge at all still stands alone (story in plans). Both edges are honored: an incoming machinery edge (a HIGH reached by same-tab navigation) joins its predecessor's run directly; an outgoing-only edge (a HIGH that opens a fresh tab and then navigates onward) flushes and leads a fresh run instead, since the run at that point may hold an unrelated leftover fragment. (2) a **side-quest is foreign by definition** (§5) — it never merges into its neighbors, never fences (MEDIUM+ structurally cannot hide), and inside a container stays a visible cut-out child; (3) **foreign hosts never merge** — same-host is a necessary condition for every join, and host = hostname with only a leading `www.` stripped (scan noise — `www` and naked variants are one identity for merging, chaining, color, and labels; recorded as-built 2026-07-24), never registrable domain (`mail.google.com` ≠ `docs.google.com`).
* **Closed proposals (2026-07-18):** *resumed-read containers* — subsumed by the MEDIUM-container path with dominance (the same-URL-anchor restriction survives as a watch-list tightening knob); *SPA-continuation merging* — subsumed by the machinery join. Stories: plans.

#### Monochrome & favicons (2026-08-07; retires hue identity)
* **No hue anywhere.** Identity (which site) and importance (how much it mattered) are fully decoupled: importance is luminance + height (above), identity is the favicon. Hostname-keyed hue, the Kelly palette, the anchor registry/tombstones, and hue-derived rims are retired — favicons don't clash with an arbitrary site color because there no longer is one.
* **Favicon-in-block, always color, clipped not withheld (2026-08-07; supersedes the fits-or-nothing/grayscale-when-unimportant rule from earlier the same day):** every real block (standalone, merged visit, container, contained child, expanded fence member — never a collapsed or fenced stick) draws its favicon, always full color regardless of tier — grayscale dimming made favicons unreadable and didn't help identify the visit. The icon is a fixed 16px anchored top-left; a block too narrow or short to fit it still renders the icon at that anchor and lets the block's own edge clip it, so a narrow block shows a partial icon rather than none. Explicitly experimental — may read poorly on very thin blocks; the "lollipop" pin alternative is retired in favor of this approach (see `WATCHLIST.md`).
* **Week strip carries no favicons** — cells stay favicon-free, painted only by the luminance/gold-border rules above; the strip answers WHEN, not WHAT (unchanged from its original mandate).
* Hover feedback = white glow + mild brighten, never a strong brightness filter.
* **On-block text labels are retired** — the favicon is the identity signal; the invariant-site-name/hostname-matching machinery that used to produce label text is unused but left in place in code, not deleted, in case a future surface (e.g. the tooltip) wants it. Site identification off the ribbon is the tooltip's job (Tooltips & snapshots).

#### Tooltips & snapshots
* **Custom tooltip layer (2026-07-15):** a self-drawn `#tip` panel with a uniform `TIP_DELAY_MS` (300ms) — native `title` tooltips have uncontrollable warm-up timing. Delegated pointerover/out/down on `#ribbon`; text set via `textContent` only (titles/URLs are page-controlled strings). The tooltip is measured at the origin before positioning (2026-07-17: a fixed-position box shrink-to-fits against the viewport edge, so measuring at the previous hover's leftover `left` squeezed it near the right edge).
* **Two-section tooltip (2026-07-18):** the user section shows the snapshot, the bold invariant site name, start time + duration (no end time), then the thread's pages — deduped member titles sorted by score descending (cap `TIP_TITLES_MAX` = 8, then "+N more"), LOW titles dimmed per the ribbon's importance-brightness vocabulary, each one line with CSS ellipsis; leading unread counters (`(379) …`) and the boilerplate segment matching the site name (`… - YouTube`) are stripped before dedupe; a lone page repeating the site name is dropped. A contained child additionally narrates its framing — `↩ interruption inside <container site> · visit N of M` (same-host siblings, chronological) — because the ribbon can't show a sub-pixel anchor-return between floored children; the hover is where the system explains itself (2026-07-18). Everything mechanical — activity counts, score/band, attended seconds, fragment/excursion counts, exact wall-clock span, per-title scores, URL — lives in a smaller dimmed debug section gated by the `TIP_DEBUG` constant (on for the demo period, off in normal use). Signals stay debug-only deliberately: users need the judgments, not the sausage.
* **Snapshot previews (2026-07-16):** block tooltips show a page screenshot above the text. **Capture (unified with the transit filter, 2026-07-24):** every session that survives the transit filter gets a capture attempt (failures soft-fail to `snapErr:` as ever) — `chrome.tabs.captureVisibleTab()` fires the moment the session first *qualifies*, one trigger per transit-exemption arm: the first interval heartbeat, the first transit-qualifying signal (keyboard/cut/copy/paste via a content-script cue; downloads background-side), OR the session's **10-second birthday on glass** (a one-shot worker timer armed at session start, `TRANSIT_MS` — the duration rung qualifies with zero signals, so hands-off survivors like cross-origin embeds and motionless reads still photograph; audit fix, later 2026-07-24). Whichever wins, one per session via an explicit `snapped` flag (never the heartbeat count — a flush beat consumes slot #1 while being barred from capture). `flush-on-hidden` beats never capture (they fire exactly while the *next* tab becomes visible — the wrong-page trap); heartbeat- and signal-triggered captures are awaited in the event queue so finalize can never outrun the store (awaiting widened from signal-only, later 2026-07-24 — an unawaited heartbeat-path store could land after finalize's deletion and leak a rejected session's picture past the sweep); the age trigger cannot race by construction — a 10s-old session has already out-aged the filter. **Finalize deletes** the `snap:`/`snapErr:` keys of any session the transit predicate rejects — the session stays stored for audit, only the picture goes. The predicate and its knobs live in `shared/transit.js` (`FS_TRANSIT`), the single source of truth for capture and display. Capture is best-effort and all failures are soft. **Opportunistic re-capture at the 3rd heartbeat (2026-08-14):** the first capture fires as early as `TRANSIT_MS`, often before a slow-loading page (Google Meet's join/lobby flow, observed specimen) has painted real content — confirmed by pulling a live specimen: `activity` showed zero discrete signals and the stored image was Meet's bare pre-join chrome. Rather than delay the first capture (which would cost every short/low-intent session, the majority), a session's 3rd real heartbeat (`current.heartbeats === 3`, same `flush-on-hidden` exclusion as the first capture — a flush beat must never trigger it) unconditionally overwrites `snap:<sessionId>` with a fresh capture. No new flag: the heartbeat counter is already monotonic, so the `=== 3` check can only ever match once per session. **Deliberately not hardened:** this is a nice-to-have, not a second admission rung — sessions that die at heartbeat 1 or 2 never get a second attempt (which is correct: short/low-intent sessions are exactly the ones this shouldn't cost), and no effort is spent making the exact-3rd-heartbeat timing bulletproof. Sessions that run to 4+ heartbeats (i.e. any session actually worth a good screenshot) get it reliably in practice. Same best-effort/soft-fail contract as the first capture — a failed re-capture just leaves the original in place. **Page text rides the original trigger only (2026-08-07):** `pageText` (§3) is extracted on the identical first-qualifying-signal moment, and a transit-rejected session has its `pageText` field deleted at finalize the same way its snapshot is — one admission bar, two artifacts. **Downscale** in the worker: JPEG capture → `createImageBitmap` → `OffscreenCanvas` → JPEG at 640px width, quality 0.6 (~20–40KB); stored as a `data:` URL under `snap:<sessionId>` (storage/retention: §2). **Display:** lazy fetch on hover; merged visits and containers show their best-scoring member that HAS a picture (the click target stays the top scorer regardless); expanded fence members show their own; collapsed sticks and fence plates stay text-only. The image is revealed only after `img.decode()` resolves, so the tooltip is measured and viewport-clamped exactly once. **Privacy (recorded deliberately):** this puts images of everything browsed on disk — fine for a personal experiment, but a real property change of the tool; "Clear data" deletes all snapshots. As-built details: `decisions/snapshot_implementation.md`.

#### Gap/duration threshold family (indexed 2026-08-06; rules audit — story in `WATCHLIST.md` "Time-threshold sprawl")
Every named gap or duration constant that gates an admission, join, split, or bridge decision, in one place — added after a rules review found them scattered across capture and display with no shared vocabulary. Grouped by what kind of evidence each one encodes; sharing a group does NOT mean sharing a value — each stays independently tunable unless noted.
* **Capture-cadence quantum (10s):** `HEARTBEAT_MS` (`content.js`, the heartbeat timer itself), `HB_WINDOW_MS` (`background.js`, idle-tail clamp), `TRANSIT_MS` (`shared/transit.js`, admission rung 2 + snapshot age-trigger) — three independently-defined constants that all encode "one heartbeat window" and currently agree by convention, not by reference.
* **Redirect/machinery noise floor:** `BLIP_MS` (2s, capture-time rung 1) and `CONTINUATION_GAP_MS` (30s, display-time — machinery join, succession join, exit inheritance) — both say "this gap is too small to be a measured absence," at two different layers (capture discards outright; display joins silently).
* **SPA view-state churn:** `SPA_DEBOUNCE_MS` (15s, capture-time URL-change absorption) — a capture-side sibling of the machinery join, healing the same fragmentation one layer down (see `WATCHLIST.md`).
* **Idle-vs-focused split:** `IDLE_SPLIT_MS` (5 min, capture-time — a focused-but-idle tab renders as absence).
* **Visit/thread-return evidence (`VISIT_GAP_MS`, 5 min):** does three independent jobs sharing one value — LOW-band absence-bridge merging (noise-tolerance), raw-fragment container-return chaining (intent-credit), and title-run splitting (labeling). Not one shared code path; three separate call sites that happen to agree. Candidate for splitting into per-purpose names if any one of the three ever needs to move independently (see `WATCHLIST.md`).
* **Assembled-object bridging:** `CONTAINER_CHAIN_GAP_MS` (10 min, second-pass container-of-containers chaining) — deliberately looser than `VISIT_GAP_MS` because a chained container is a coarser claim than a raw fragment.
* **Departure/"walked away" evidence (30 min):** `AUDIO_BOOKEND_GAP_MS` (container gap-audio bridge — the tab's own audio testifies) and `FENCE_BRIDGE_GAP_MS` (away-plate gate ONLY as of 2026-08-08, below — a wall-clock judgment about leaving the machine) currently agree at 30 min but are **two independently-defined constants, not one** — the code deliberately keeps them separate (different evidence: one is a fact about the tab, the other a fact about the user), and nothing enforces they stay equal. Retuning one without the other is a legitimate design choice, not a bug, but should be a deliberate one. `FENCE_BRIDGE_GAP_MS` no longer gates fencing itself — see the implied-break entry below.
* **Lock-confirmed departure (2026-08-08):** a recorded `locked` interval (§3) inside a fence gap is a duration-free, unconditional split — no constant to tune, since it isn't a threshold. The one break signal in this family backed by a machine-level fact rather than a wall-clock guess.
* **Implied-break fold (60 min, 2026-08-08):** `FENCE_IMPLIED_BREAK_MS` gates fence bridging for gaps with NO lock evidence — the successor to the old fence threshold, raised because it no longer has to proxy for "did they really leave" (the lock check now answers that directly when it can). Independent of `FENCE_BRIDGE_GAP_MS`, which stays at 30 min and now gates only the away-plate hover, not fencing.
* **Terminal-action discount:** `TERMINAL_KEY_MS` (500ms — the close-chord keystroke that doesn't count as engagement).
* **Copy/cut floor (20s, seconds not ms — the one outlier unit in this family):** `COPY_CUT_FLOOR_ATTENDED_S` gates the copy/cut scoring discount.
