## 5. Design Philosophy: The Noise/Signal Tightrope (agreed 2026-07-15; restructured thread-first 2026-07-18 — story in `decisions/rules_restructure.md`)

**The thesis of this experiment:** when is a series of quick visits noise to hide, and when is one an important moment to highlight? The answer: **importance is evidenced by intent, not duration.** Duration tells you where attention *sat*; discrete signals (copy, paste, keystrokes, downloads) tell you where attention *acted*. A 15-second visit with a `copy` is a fundamentally different object than a 15-second bounce. This is why activity is captured as per-signal, per-type counts and never summed.

### Two layers, one direction (2026-07-18)
Capture records **sessions** — continuous focus on one URL in one tab, granular and unjudged. Display assembles **threads** out of them (§6). Information flows one way: display never feeds capture, and capture never pre-aggregates.

### The boundary taxonomy (2026-07-18)
Every session boundary carries its recorded reason, and the reason — not the gap size — decides its display fate:
* **Machinery** (`spa_navigation`, `navigated` — attention never left the tab): not an event. Joined silently into the thread.
* **Departure** (`tab_hidden` mid-thread, with a later return): an interruption — returning is the strongest intent signal we have. Never erased, never merely adjacent: **framed** — the thread becomes a container and the interruption a visible child (or the departure count itself testifies when it left the browser).
* **Absence** (gap ≥ `VISIT_GAP_MS` to the next same-thread fragment): a real break, preserved as a gap. Spanned only by the gap-audio exception (§6 — the tab's own audio testifies through a long excursion; replaced the audio-bookend proxy 2026-07-24).
* **The remaining reasons (classified 2026-07-24):** `tab_closed` is terminal by default — machinery only under the succession license (same-tree same-host successor, < 30s — §6). `idle_split` is **absence made explicit by capture**: the split *manufactures* its gap, so it is never machinery and never departure testimony (the user never left the tab, so there is no return-intent to credit).

This replaces the 2026-07-15 "strict adjacency / gap-tolerant merging is forbidden" prohibition. The presumption flipped with data: boundaries are machinery unless their reason testifies otherwise, and it is *separation* that needs justification — a departure, an absence, a foreign host, or an individually-HIGH block.

### Thread taxonomy (recast 2026-07-18 from the block taxonomy)
* **Bounce** — sub-quantum, signal-free. Never admitted (§3 admission filter) or, at LOW, rendered at the `MIN_W` floor.
* **Side-quest** — short but carrying discrete intent, and **foreign by definition** (the B in A→B→A). Highlighted *despite* brevity; never absorbed (§6 atomicity). Canonical case: a long Docs session, a brief tab-out to copy an image, return — the side-step is a key event even though it splits the Docs thread.
* **Thread (dwell generalized)** — same-host engagement accumulating across machinery boundaries and departures; sized and tiered by its summed attention and intent.

### Consequences
* **Horizontal Lifestreams rendering:** width = time, salience (height/brightness/badge) = intent. A side-quest is honestly thin but visually bright, so brief-but-important punches above its width.
* **SPA debounce stance:** the 15s debounce (Edge Case 3) blurs *which page within a site* a quick action happened on (signal counts survive; URL granularity is lost). Accepted; with the display-side continuation merge now healing the same fragmentation, the overlap is watch-listed (§6).

### Capture roadmap addition: `download` signal (implemented)
Copying an image we see; "Save image as…" fires no DOM event and is invisible to the content script. `chrome.downloads.onCreated` in the background (requires the `downloads` permission) increments the current session's `download` count — likely the strongest single intent signal we have. Background-observed: it does not ride the heartbeat.

**Presence gate (2026-07-26):** a `download` event only counts if the session already has proof of user presence — a heartbeat, or a click (via a real-time click cue, since `activity.click` otherwise only arrives batched on the next heartbeat). Same bar as Rung 1 session admission (one click OR one heartbeat), applied in real time so it can gate a signal mid-session rather than only at finalize. Presence-less downloads are dropped, not deferred. Fixes a torrent-client tab (`utweb.rainberrytv.com`) firing 1500+ `onCreated` events on tab restore after reboot, with zero attended time — the web UI replays its download history to the browser on reconnect, none of it user-initiated. (Story: `decisions/capture_design.md`.)

### The missing axis: activity-induced intent vs. social context (2026-08-06, acknowledged limit, not a task)
Everything above — Score v1, tiers, containers, earned-HIGH — measures **activity-induced intent**: what the user *did* on a page. A message to your boss and a message to your dentist can produce identical activity (same dwell, same keystrokes, same scroll) and will score identically, by design, because the formula only ever looks at behavior, never at who or what the correspondence concerns. This is a ceiling, not a tuning gap: no amount of polishing the activity model reaches **social context** (who/what matters to the user) — it is a structurally different axis that activity data cannot encode on its own. Recorded deliberately as a standing open question, not a backlog item — no capture or scoring change is proposed here. (Emerged from the Gmail focus-label discussion, 2026-08-06 — story in `decisions/timeline_design.md`.)

## 6. UI/UX Directives

**Rules only.** Evidence, dated history, and rejected alternatives live in `decisions/` — display decisions in `decisions/timeline_design.md`, tooltips/snapshots in `decisions/snapshot_implementation.md`. A date tag like (2026-07-16) marks when a rule was agreed; the story behind it is in plans.

### Debug tools (session list removed 2026-07-17)
The dashboard (`dashboard/index.html`, opened full-tab by the toolbar icon, which also console.tables all sessions in the worker console) carries the debug surfaces. The per-session list was removed 2026-07-17 — its jobs were already covered (raw inspection = console dump, tuning = Score table, per-block detail = tooltips).
* **Score table** button: scores every stored session with the live §6 formula via `window.FS_SCORING` (exported by timeline.js — single source of truth, so diagnostics can't drift), logs a `console.table` sorted by score with band counts, and copies TSV to the clipboard. Columns: host, title, secs, attended, hb, aud, kbd, copy, cut, paste, dl, keyGap (terminal-keystroke audit, 2026-07-24), click, mouse, scroll, scr(ollable), score, band, tabId, opener (tab-tree audit, 2026-07-19), start (epoch ms), reason, url — enough to re-score weight candidates and replay chain-rule candidates offline.
* **Clear data** button (with confirm): wipes sessions and all snapshots (enumerate with `getKeys()`, never `get(null)`).
* Session-area writes (the live session's 10s heartbeats) refresh only the header count; local-area writes (finalize, color claims, Clear) repaint everything. The ribbon pipeline must never re-run on heartbeats.

### Search (2026-08-06)
A "find and go" tool in the header, independent of day paging and thread assembly — results are raw stored sessions, not display atoms. Plain case-insensitive substring match; a multi-word query requires every word present (AND), each word matched against title OR url OR `pageText` (§3) — `pageText` itself is never shown in a result row, only used to match. Results group by exact URL, then by title within that URL (same page/title revisited collapses to its most recent visit; distinct titles at one URL, e.g. different Gmail threads, each surface as their own row), sorted newest-first, capped at 20 rows. Click opens the page in a new tab.

**Self-exclusion:** the extension's own pages are never tracked — subsumed by the web-documents-only capture rule (§3 lifecycle semantics).

### Horizontal Timeline (design adopted from Desktop4, 2026-07-15)
Rendering model ported from the Desktop4 demo (`~/Projects/Desktop4 (lifestreams)`) as pure functions on vanilla DOM/CSS; its WebGL/React stack did not come along.

#### Layout & day navigation
* A single horizontal ribbon: X = chronological time; block width = true duration × scale, floored at `MIN_W` (large blocks stay near-proportional; only slivers stretch the day). Visual identity (2026-08-07 monochrome pass): dark background, luminance-filled blocks with a lighter border rim, hover glow, in-block favicons, short white hour ticks + dim labels below. Horizontal zoom is supported (2026-08-08, below); no background grid (a uniform grid implies a uniform time scale, which the two-scale axis contradicts — zoom scales both scales together, so this still holds at every zoom level).
* **The timeline is the PRIMARY view (2026-07-15).** Size the ribbon generously — big band, legible type. Page layout (2026-07-17, revised 2026-08-25): header (search + debug buttons), ribbon near the top, the space below kept open as clearance for snapshot tooltips. The whole page is dark.
* **Days load by zooming out, not by picking (2026-07-16, replaced 2026-08-25):** a session still belongs to the day it **ends** in, and viewing today still live-updates, but there is no day *picker* — the ribbon is right-anchored at today and reaches backward one day at a time as the user zooms out (§7e), capped at the 7-day retention window. All day-picking UI is retired: the week strip, its skyline cells, and arrow-key paging. Right-anchoring and cross-day loading are one change, not two — the picker existed because a left-anchored ribbon showed exactly one day.

#### Time scales & hour axis
* **Two time scales (2026-07-15; both halved 2026-07-17):** presence renders at `PX_PER_SEC` = 0.0375 (135px/hr — sized to a NORMAL day so a light day reads light); absence at `GAP_HOUR_PX` = 22 per absent hour (~1/6 speed). Everything is linear in these two constants: hour ticks interpolate through blocks and gaps alike, and **hour boundaries have no width effect anywhere**, including the leading pad (an 8:47 first block sits proportionally after the 8am tick at gap scale). Whole hours inside a long absence render evenly spaced — countable. Gap regions ≥ ~6px carry an invisible hover plate with the exact away-span ("away 11:23 AM – 3:12 PM · 3h49m"). `MIN_W` = 8 absorbs the small end (blocks under ~3m33s render at the floor). Fixed widths (`MIN_W`, `GAP`) do NOT scale with `PX_PER_SEC` — if dense stretches read too wide, tune the overhead constants, not the scale — and this holds at every zoom level too (below), not just at the base scale. Scale history (540 → 270 → 135px/hr) and rejected alternatives (fit-to-viewport, nonlinear width, break glyphs, uniform slots): plans.
* **Horizontal zoom (2026-08-08):** `PX_PER_SEC` and `GAP_HOUR_PX` are each `BASE_* × zoom` — a single factor (range `ZOOM_MIN` – `ZOOM_MAX`, default 1; values widened to 0.25–16 on 2026-08-23 for §7e cross-day zoom-out — `spec/ribbon.md` §7e is authoritative for them) scaling both time scales together, preserving the presence:absence ratio at every zoom level. Real relayout, not a CSS transform: `layout()` re-runs from scratch on the live scaled values, so borders/text/favicons stay crisp and `MIN_W`/hour-label-thinning logic keep operating on true pixel geometry (a transform would blur all three and desync the label-thinning math from what's on screen). **Trigger:** wheel/trackpad over the ribbon — `deltaY` zooms (exponential curve, `ZOOM_SENSITIVITY`), `deltaX` pans via the wrap's native `scrollLeft`; both fire from one diagonal trackpad gesture. The ribbon claims ALL wheel input unconditionally (`preventDefault`) rather than passing vertical scroll to the page — deliberate, since the dashboard is a single-view page with nothing below the ribbon to scroll to. **Anchor:** the pointer's x-fraction of the ribbon's total width is captured before relayout and restored after (via `scrollLeft`), so the timestamp under the cursor stays under it — proportional-position anchoring, not a true timestamp inversion, but equivalent here since both scales move by the same factor. **Cost:** zoom relayout skips thread/container (re)assembly entirely — a cached last assembly is repainted (`relayout()`), not rebuilt (`render()`) — coalesced to one pass per animation frame via `requestAnimationFrame`, so a continuous gesture stays cheap. **Transition suspended during zoom:** `.blk`'s day-paging CSS transition is switched off (`#ribbon.zooming`) for the gesture's duration (lifts `ZOOM_IDLE_MS` after the last tick) — the transition is correct for discrete jumps but would read as smeared lag under a continuous 60fps zoom. Zoom level persists across day paging, refresh, and live updates (nothing resets `zoom`) — it is a viewing preference, not part of a day's data.
* **Hour axis (2026-07-15):** whole-hour labels only — no minute labels; the tooltip carries the exact wall-clock span (`8:47 AM – 8:58 AM`) as ground truth (2026-07-18: in its debug section — the user section shows start + duration). Hour marks are time-interpolated within whichever block or gap was active then — never assumed linear (widths are floored).
* **Crowded hour labels drop the meridiem (2026-07-17):** every mark first renders the full "9am/12pm" form, then drops to the bare number only when the full label's **measured** half-width + `LABEL_CLEARANCE` would spill past the midpoint to the next mark — room is measured geometry, not gap membership. Only the NEXT mark is tested, so a run's last label always keeps its meridiem — it is the run's anchor ("… 3 4 5pm"). Long absences read "9 10 11 12 1 …"; meridiem flips are implied by context. Backstop: left-to-right label collision thinning — a collider drops, never nudges. **Ticks are never thinned** — the countable-hours property is tick-borne. **Labels are centered under their ticks (2026-07-17)** in a row below the tick row — each label owns its inter-mark column instead of racing the next tick in the same lane.

#### Importance: one score, three tiers, two heights
* **Bottom-flush heights (2026-08-08):** `TIER_H` — HIGH 144px / MEDIUM 108 / LOW 108 on the 144px band. HIGH keeps the full band; MEDIUM and LOW drop to 75% and share one height, so the only height step on the ribbon is the one that marks HIGH. The top edge is the importance contour. Width is time; height is salience (§5). Story: `decisions/timeline_design.md`, "MEDIUM/LOW drop to 75% of HIGH".
* **Importance brightness — three-step ladder (2026-08-08; supersedes the 2026-08-07 two-step "only HIGH is bright" rule, which had made MEDIUM and LOW run together):** LOW paints `#262626` / `#3A3A3A`; MEDIUM paints its own midpoint step, `#323232` / `#4E4E4E`; HIGH paints the brightest, `#3D3D3D` / `#6B6B6B` — every tier now reads apart by fill/border alone. Brightness is the only signal separating MEDIUM from LOW, which share a height (above). Score/band computation is unaffected — transitional, pending further scoring work.
* **Earned HIGH (2026-08-07):** a thread's tier is the band of its SUMMED fragments, which conflates two different shapes of intent — one fragment that was individually HIGH (a real, concentrated moment) vs. several lesser fragments piling up via revisits/`W_NAV` traversal until the sum crosses `HIGH_SCORE`. A HIGH-band container/block whose underlying members include ≥1 individually-HIGH fragment gets a semantic accent border, `#D4AF37` (muted gold), replacing the standard important border — on the container/block itself only, never on contained children, which already have their own display treatment.
* **The fence — REMOVED 2026-08-25:** LOW runs used to collapse to thin 3px sticks with a hover-to-expand plate, so LOW noise would not read as equally worth attention alongside MEDIUM/HIGH. It had not rendered since §8 Phase 1 earlier the same day (run-building was gated on `anchorMode !== "right"`, permanently false once the overlay was deleted), and the code came out rather than staying dormant: `clusterEvents`, `gapIsLockBounded`, `MIN_RUN`, `STICK_W`/`STICK_GAP`/`STICK_FILL`, `FENCE_IMPLIED_BREAK_MS`, the whole expand/collapse interaction, and `.plate` CSS. `layout()` now takes plain events — there is no cluster/item wrapper. The away plate survives and is unrelated (below). Story and the rules as they stood: `decisions/timeline_design.md`.
* **Clicks (2026-07-15):** click means "open this page" on every block, everywhere — expanded members navigate, never re-collapse. Collapse = the expand bar (a ~16px hit zone around its 4px visual) or Escape. The expand bar lives in its own lane: bar snug under the band, clear gap, then hour ticks/labels — no vertical overlap.

#### Score v1 (FocusStream units)
```
attendedSeconds = max(heartbeats × 10, audibleMs / 1000)
                  // measured attention: active windows OR audible playback
                  // (max, not sum — same-frame video counts in both)
copyCutWeight = attendedSeconds <= 20 ? 80 : 150
                  // floor-attended discount (2026-08-02, below)
score = attendedSeconds
      + copyCutWeight × copy + copyCutWeight × cut + 80 × paste
      + 200 × download                      // strongest intent signal we have
      + min(keyboard, 200)                  // 1/keystroke, capped: composition ≈ copy-tier
      + 5 × scroll, ONLY when scrollable    // the "read" premium (added 2026-07-15)
Tiers: HIGH ≥ 1000, MEDIUM ≥ 150
```
* Simpler than Desktop4's formula by design: heartbeats measure attention directly, and background tabs can't inflate dwell (sessions only exist while visible + focused). mouse/click/media contribute via `attendedSeconds` (they make windows active), not separate weights.
* **Floor-attended copy/cut discount (2026-08-02):** a session at or below 20s attended time (≤2 heartbeats) whose ONLY real signal is a copy or cut click scores MEDIUM off that single click alone — `W_COPY` (150, shared by cut — one constant, not two) plus a floor attended value already exceeds `MED_SCORE` (150), regardless of what was actually copied or what page it happened on. At this attended floor a copy reads as copying-in-passing (a stray selection, an SMS 2FA code), not the deliberate composition the full weight is calibrated for, so both weights drop to `W_PASTE`'s tier (80) — parity with paste's existing "clipboard thing happened, can't tell if it mattered" treatment. Above the 20s floor, copy/cut are unchanged; sessions with real composition naturally clear the floor via attended time. `W_PASTE` itself is untouched. Attended time alone gates the discount — keyboard count forms a smooth continuum with no natural noise/signal split, so a `kbd` co-condition was rejected as arbitrary (week replay + rationale in `decisions/timeline_design.md`).
* **The scroll term — "the read" (2026-07-15):** `W_SCROLL` = 5 per active scroll window, **gated on `scrollable = true`** — the gate is load-bearing: app-style SPAs scroll an inner container, so `documentElement.scrollHeight` never exceeds the viewport and feeds/Maps noise reads `scrollable = false` by architecture. Merged visits and containers inherit `scrollable` as the OR of their members. Validation method + numbers: plans.
* **The traversal term — `W_NAV` (2026-07-24, provisional):** thread assembly adds `W_NAV` (50) per join, on top of the summed member totals — a merged visit adds `W_NAV × (members − 1)` (machinery navigations and absence-bridge returns alike) and a container chain adds a further `W_NAV × (fragments − 1)` (returns). Multiple committed page views within a domain are intent the per-signal totals can't see, and the joins counted are exactly the survivors of the SPA debounce, blip filter, and transit filter — view-state churn and redirect machinery contribute nothing by architecture. No user-act gate (rejected on data). Tuned on ONE real day — **retest with a fuller week before touching it** (see `WATCHLIST.md`); validation + rejected alternatives: plans.
* **⚠ Provisional:** all weights/thresholds are Desktop4-inherited. Keep every weight a named constant; thresholds held while label gating is evaluated (one knob at a time).
* **`heartbeats` capture:** one integer per SessionBlock — total active heartbeats received (NOT derivable from per-signal counts, which overcount multi-signal windows). Max-scroll-depth capture rejected (2026-07-15): it gates against background-tab dwell, a pathology our capture model structurally prevents.

#### Aggregation: threads (restructured 2026-07-18; component rules agreed 2026-07-15 through 2026-07-18)
* **The thread is the display atom (2026-07-18).** A thread is a maximal chain of same-host fragments in one **tab tree** (2026-07-19: tabs connected by stored opener edges resolve to one root — "one tab and its spawn"; an edgeless tab is a tree of one, so cold tabs and pre-opener data behave exactly as before), joined across machinery and succession boundaries and — **by framing only** — across departures (§5 boundary taxonomy; a departure chain that fails container qualification stands apart as separate blocks), broken by absences, foreign hosts, and atomicity (below). Score/tier = band of the **summed** fragments — add up, then judge. A single unmerged session is a thread of length 1; no special rules. Display-time only; capture stays granular.
* **Thread assembly — merging:** three joins build visit blocks before fencing, scored and banded on the merged totals. Two share one named sanity-bound constant, `CONTINUATION_GAP_MS` (30s — "attention never really left": gaps this size are noise on a machinery boundary, not a measured absence). Each join adds the traversal term (`W_NAV`, Score v1; 2026-07-24). Click opens the top-scoring member; the tooltip lists the member pages (Tooltips & snapshots). Story: `decisions/timeline_design.md`.
* **Join 1 — machinery (2026-07-18; HIGH included 2026-08-06):** same-tab same-host neighbors whose boundary is `spa_navigation`/`navigated` (< `CONTINUATION_GAP_MS`) merge **regardless of band**. Three back-to-back YouTube videos are one watch, and a HIGH video mid-binge no longer splits it in two (Atomicity).
* **Join 2 — succession (2026-07-24; HIGH pass-through fixed 2026-08-07):** same-**tree** same-host neighbors whose boundary is `tab_closed` (same `CONTINUATION_GAP_MS` bound) merge **regardless of band** — closing a finished tab to land on the next queued same-host tab is cross-tab machinery, not departure (the middle-click batch pattern). The tree key is the intent test: a stray same-host tab in another tree never joins. A HIGH fragment joins on an incoming edge (it lands on the queued tab) but an outgoing-only edge flushes and leads a fresh run instead — the run may hold an unrelated leftover fragment. `tab_hidden` never merges: the user actually left, which stays container territory.
* **Join 3 — absence-bridge (2026-07-15):** consecutive same-host **LOW** blocks with gaps < `VISIT_GAP_MS` (5 min) merge — noise-level grazing may bridge small absences; anything with signal may not. Deliberately **host-keyed, not tab-keyed** (2026-07-18): LOW grazing is site-level behavior, and requiring same-tab would fragment noise for purity's sake — the one licensed exception to the thread's one-tab definition.
* **Merged-visit behavior:** merged visits carry their last member's `endReason`, so merged fragments can testify as departures.
* **Exit inheritance (2026-07-24):** the transit filter drops a stub's presence, never its boundary testimony. A dropped stub that would have machinery-joined its same-tab **same-host** predecessor (the FULL join conditions: machinery boundary, < `CONTINUATION_GAP_MS`, same host) bequeaths its `endReason` to that predecessor — a visit's exit is its last member's exit — so succession joins and departure testimony survive the filter. A foreign-host stub was never a would-be member and must not manufacture succession licenses.
* **Thread shape — solid or container (2026-07-15):** a thread with no interruptions renders as one solid block (width = summed duration). A thread the user kept *returning* to renders as a **container** — returning is the strongest intent signal we have: width = wall-clock **SPAN** (the one exception to width = duration, which makes containment geometrically possible), foreign events inside the span drawn as **contained children**. Same object, two silhouettes — joined by continuity, framed by return.
* **Container qualification — chain eligibility:** same-tree **same-host** fragments chain (2026-07-19; keyed on the (tree, host) pair — a spawned foreign-host read neither joins nor breaks its parent's chain; the covered-HIGH guard is tree-blind, 2026-07-24, see Atomicity) when the return gap is < `VISIT_GAP_MS`, OR < `AUDIO_BOOKEND_GAP_MS` (30 min) on **gap-audio testimony**.
* **Gap-audio testimony (2026-07-24; URL continuity added 2026-08-24):** the resuming fragment's `audibleSinceTs` predates the previous fragment's end — the tab demonstrably kept playing while the user was away (a meeting talks through its whiteboard gap; a paused video cannot testify). Additionally requires the resuming fragment's URL to equal the previous fragment's: the audio proves *the tab* never went silent, never that the *same activity* continued. Pre-2026-07-24 sessions lack the stamp and never long-bridge — fails closed. Replaces the audible-dominated bookend proxy (≥50% of duration). Story: `decisions/capture_design.md`, "Audible continuity"; `decisions/timeline_design.md`, "Back-to-back same-host events".
* **Containerization test:** a chain containerizes when all three hold — **summed score ≥ MEDIUM** (2026-07-18; tier = band of the sum, which includes the traversal term for returns, Score v1); **≥1 interruption** exists, meaning a foreign child in the span OR a departure boundary (a non-final fragment ending `tab_hidden`, 2026-07-16 — machinery boundaries never count, so continuous same-tab reading can't self-containerize); and, below HIGH, **anchor dominance** holds, anchor sum > children sum (a weak anchor framing stronger children is a launcher — the children are the story; deliberately not applied ≥ HIGH).
* **Spawn-edge dominance discount (2026-07-25):** a child whose tab's stored opener path reaches a chain member's tab (≥ 1 edge; the anchor's own tab never counts, so same-tab redirect interleaves keep full weight) is the anchor's own dispatch and drops out of the dominance denominator. The anchor must still **individually** outscore every discounted spawn — a chain never frames a single event bigger than itself. Fails closed on pre-opener data.
* **Overlapping qualifying chains (revised 2026-07-19; was winner-take-all):** higher sum wins the contested span, but the loser is **trimmed, not discarded** — fragments overlapping an accepted container drop out (span-covered ones become its children), and the remainder re-enters the contest as runs, re-summed and re-qualified. A handoff between two threads frames as flush sequential containers instead of one winner shattering its rival's uncontested run.
* **Adjacent-container chaining — pass two (2026-08-02):** container-building is a two-pass recursion of the same chain-and-qualify logic. Pass one chains raw fragments at `VISIT_GAP_MS`; pass two re-runs it on its own output (containers and leftover merged visits alike, same (tree, host) key, same guards — flatten, no nesting) at the looser `CONTAINER_CHAIN_GAP_MS` (10 min). An assembled container is a coarser claim than a raw fragment, so it earns a longer bridge. 10 min is a judgment call, not data-derived — no natural cliff in a week's gap distribution (see `WATCHLIST.md`).
* **Earned-HIGH atomicity in chaining (pass two 2026-08-07; pass one on URL change 2026-08-24):** a container/visit that `hasEarnedHigh` never bridges in pass two, on **either** side of the gap. An earned-HIGH container is a resolved, standalone event; bridging it erases a boundary rather than completing a story (specimen: two back-to-back Google Meet calls fused into one). The same guard applies in pass one, but ONLY when the two fragments' URLs differ — so an ordinary same-URL revisit chains exactly as before, and this is not the universally-URL-keyed chaining rejected 2026-08-07. Watch `earned-high-pass-one-reach`.
* **Weak-bridge guard (2026-08-14):** a bridge additionally requires at least ONE endpoint to carry a MEDIUM+ **edge fragment** — but ONLY when a real excursion (another host, different tree, chronologically between) actually filled the gap; an empty gap never trips it, since returning after a plain pause is the strongest intent signal there is. "Edge fragment", not the endpoint's own `.band`, because in pass two an endpoint can be an assembled container whose band says nothing about the ONE fragment touching this gap — the guard walks to the chronological edge, recursively through nesting. Prevents a chain qualifying on strength earned entirely AFTER the bridge, which would sweep an unrelated excursion in as children. Per-bridge, not whole-chain.
* **Container display (2026-07-17):** a container paints exactly like a solid block of its tier — same fill, rim, hover. Click opens the top-scoring fragment; the tooltip lists the anchor's pages, with span and counts in its debug section. Zero-children containers need no special case (the tooltip's "(interruptions outside the browser)" line marks them).
* **Children are cut out of the interior (2026-07-17):** drawn on top at time-proportional positions, in normal proportional block width regardless of band, capped at MEDIUM — containment frames, never confers, never destroys. No labels inside (hover only). The container stretches if min-width children would overflow.
* **The cut seam is 1px (narrowed from 2px, 2026-08-02):** a page-background seam separates each child from the container. The width lives in CSS (`.blk.cut`), not in JS. Story: `decisions/timeline_design.md`, "Tightening the cut".
* **Contained children are inset top and bottom (2026-08-02):** `CONTAIN_INSET` (6px) shaves the child's top edge so a same-tier child (e.g. MEDIUM-in-MEDIUM) still shows a strip of container above it; `CONTAIN_BOTTOM_INSET` (1px) matches the container's own border width so its bottom border shows through. Deliberately asymmetric — not a padding pair. Story: `decisions/timeline_design.md`, "Tightening the cut".
* **Contained LOW sticks — RETIRED (2026-08-07, same pass as the top-level fence retirement):** a LOW child used to render as a 3px fence stick cut into the container; it now renders as a normal proportional-width block like MEDIUM/HIGH children, capped at the same uniform contained-child height (below). `STICK_W` went with the fence (2026-08-25); `CUT_SEAM` is defined but unused — the seam width is CSS-side (above). Story: `decisions/timeline_design.md`.
* **Contained children render at one uniform height (2026-08-07):** all contained children render at `CONTAIN_CHILD_H` — 50% of the full band (`BAND_H / 2` = 72px) — independent of `TIER_H`. Containment frames, never confers stature.
* **`TIER_H` is the one tier-height source (2026-08-25):** every block gets its height from `TIER_H`. It was dormant from 2026-08-11 while the card deck sized from its own `CARD_TIER_H`; that path was deleted 2026-08-25, so `TIER_H` is live and sole again.
* **Atomicity — what a thread may never swallow (unified 2026-07-18; guards agreed 2026-07-15):** three guards, below. Story: `decisions/timeline_design.md`.
* **Guard 1 — an individually-HIGH session owns its story against foreign frames (relaxed 2026-07-19; was absolute):** it never joins a foreign-host chain (structural since 2026-07-19 — chains key on the (tree, host) pair, so a HIGH can only extend its own host's thread), and any chain whose span would cover it is rejected **regardless of tab tree** (2026-07-24): containment is a demotion, earned by evidence, never inferred from time-overlap. The audio-licensed re-join for meeting-framed HIGHs awaits a specimen (`WATCHLIST.md`).
* **Guard 1 tests only covered NON-members.** A HIGH inside its own host's chain in its own tree is a fragment, not a child — it cannot break its own thread's container, so it MAY seed or join **its own host's chain in its own tab tree**. Same-host chaining credits the thread; excluding the anchor's HIGHs was decapitating true anchors in territory contests.
* **Guard 1 exception — same-tab machinery pass-through (2026-08-06; incoming-edge bug fixed 2026-08-07):** a HIGH fragment MAY join the **machinery join** (merge, not chain) when at least one edge to a same-tab same-host neighbor is `spa_navigation`/`navigated` — attention never left the tab, so the boundary is page turnover, not a foreign frame. A HIGH with no machinery edge stands alone. Both edges honored, same asymmetry as the succession join: an incoming edge joins its predecessor's run; an outgoing-only edge flushes and leads a fresh run, since the run may hold an unrelated leftover fragment.
* **Guard 2 — a side-quest is foreign by definition (§5):** it never merges into its neighbors, and inside a container stays a visible cut-out child.
* **Guard 3 — foreign hosts never merge:** same-host is a necessary condition for every join. Host = hostname with only a leading `www.` stripped (scan noise — `www` and naked variants are one identity for merging, chaining, color, and labels; as-built 2026-07-24), never registrable domain (`mail.google.com` ≠ `docs.google.com`).
* **Closed proposals (2026-07-18):** *resumed-read containers* — subsumed by the MEDIUM-container path with dominance (the same-URL-anchor restriction survives as a watch-list tightening knob); *SPA-continuation merging* — subsumed by the machinery join. Stories: plans.

#### Monochrome & favicons (2026-08-07; retires hue identity)
* **No hue anywhere.** Identity (which site) and importance (how much it mattered) are fully decoupled: importance is luminance + height (above), identity is the favicon. Hostname-keyed hue, the Kelly palette, the anchor registry/tombstones, and hue-derived rims are retired — favicons don't clash with an arbitrary site color because there no longer is one.
* **Favicon-in-block, always color, clipped not withheld (2026-08-07; supersedes the fits-or-nothing/grayscale-when-unimportant rule from earlier the same day):** every real block (standalone, merged visit, container, contained child) draws its favicon, always full color regardless of tier — grayscale dimming made favicons unreadable and didn't help identify the visit. The icon is a fixed 16px anchored top-left; a block too narrow or short to fit it still renders the icon at that anchor and lets the block's own edge clip it, so a narrow block shows a partial icon rather than none. Explicitly experimental — may read poorly on very thin blocks; the "lollipop" pin alternative is retired in favor of this approach (see `WATCHLIST.md`).
* Hover feedback = white glow + mild brighten, never a strong brightness filter.
* **On-block text labels: retired 2026-08-07, then reinstated as `.blk-label`** — an always-on inline site name on the block face, alongside the favicon. It is now the ribbon's ONLY on-face identity text (below).
* **Floating labels — REMOVED 2026-08-25:** two mechanisms drew site names *above* the band and both are gone. (1) The **quick label**: hovering a LOW/MEDIUM block showed its site name instantly, styled like a run title, so a run of small blocks could be swept by eye without waiting out `TIP_DELAY_MS` per block. (2) **`.rtitle` run titles**: persistent on-face labels centered over runs of consecutive same-host HIGH blocks, which glided with their blocks across repaints (`titleRuns`/`groupRuns`). Both were retired in the overlay on 2026-08-22/25 as redundant with the always-on `.blk-label`, gated behind `anchorMode !== "right"` — and so had not rendered anywhere since §8 Phase 1. Deleted outright on 2026-08-25 rather than restored, because the redundancy argument never depended on which surface was showing. `TITLE_AREA` (24px above the band) survives as band geometry — block tops, the axis strip and the parked tip all measure from it — but no longer holds labels. Story: `decisions/timeline_design.md`.

#### Tooltips & snapshots
* **Custom tooltip layer (2026-07-15):** a self-drawn `#tip` panel with a uniform `TIP_DELAY_MS` (300ms) — native `title` tooltips have uncontrollable warm-up timing. Delegated pointerover/out/down on `#ribbon`; text set via `textContent` only (titles/URLs are page-controlled strings). The tooltip is measured at the origin before positioning (2026-07-17: a fixed-position box shrink-to-fits against the viewport edge, so measuring at the previous hover's leftover `left` squeezed it near the right edge).
* **Two-section tooltip (2026-07-18):** the user section shows the snapshot, the bold invariant site name, start time + duration (no end time), then the thread's pages — deduped member titles sorted by score descending (cap `TIP_TITLES_MAX` = 8, then "+N more"), LOW titles dimmed per the ribbon's importance-brightness vocabulary, each one line with CSS ellipsis; leading unread counters (`(379) …`) and the boilerplate segment matching the site name (`… - YouTube`) are stripped before dedupe; a lone page repeating the site name is dropped. A contained child additionally narrates its framing — `↩ interruption inside <container site> · visit N of M` (same-host siblings, chronological) — because the ribbon can't show a sub-pixel anchor-return between floored children; the hover is where the system explains itself (2026-07-18). Everything mechanical — activity counts, score/band, attended seconds, fragment/excursion counts, exact wall-clock span, per-title scores, URL — lives in a smaller dimmed debug section gated by the `TIP_DEBUG` constant (on for the demo period, off in normal use). Signals stay debug-only deliberately: users need the judgments, not the sausage.
* **Snapshot previews (2026-07-16):** block tooltips show a page screenshot above the text. Capture, storage and the admission bar are capture-side rules — **`spec/capture.md`, "Snapshot capture"**.
* **On-block snapshots (2026-08-25):** MEDIUM/HIGH blocks paint their snapshot on the block face, not only in the tooltip; LOW stays flat tier fill. The image fits the block's WIDTH (`min-width` floors the scale, so a narrow block clips rather than smearing) at full height, `object-fit: cover`, anchored left/top so its left edge is the session's start. Favicon and label sit above it over a flat 24px scrim at 0.5 — explicit `z-index` orders image/scrim/text, since `::before` would otherwise paint under the image. Fetch is lazy and viewport-culled — a pan must not fetch every picture it crosses. Story: `decisions/snapshot_implementation.md`.
* **Snapshot display (tooltip):** lazy fetch on hover. Merged visits and containers show their best-scoring member that HAS a picture (the click target stays the top scorer regardless). The image is revealed only after `img.decode()` resolves, so the tooltip is measured and viewport-clamped exactly once.
* **Privacy (recorded deliberately):** this puts images of everything browsed on disk — fine for a personal experiment, but a real property change of the tool. "Clear data" deletes all snapshots. As-built details: `decisions/snapshot_implementation.md`.

#### Gap/duration threshold family (indexed 2026-08-06; rules audit — story in `WATCHLIST.md` "Time-threshold sprawl")
Every named gap or duration constant that gates an admission, join, split, or bridge decision, in one place — added after a rules review found them scattered across capture and display with no shared vocabulary. Grouped by what kind of evidence each one encodes; sharing a group does NOT mean sharing a value — each stays independently tunable unless noted.
* **Capture-cadence quantum (10s):** `HEARTBEAT_MS` (`content.js`, the heartbeat timer itself), `HB_WINDOW_MS` (`background.js`, idle-tail clamp), `TRANSIT_MS` (`shared/transit.js`, admission rung 2 + snapshot age-trigger) — three independently-defined constants that all encode "one heartbeat window" and currently agree by convention, not by reference.
* **Redirect/machinery noise floor:** `BLIP_MS` (2s, capture-time rung 1) and `CONTINUATION_GAP_MS` (30s, display-time — machinery join, succession join, exit inheritance) — both say "this gap is too small to be a measured absence," at two different layers (capture discards outright; display joins silently).
* **SPA view-state churn:** `SPA_DEBOUNCE_MS` (15s, capture-time URL-change absorption) — a capture-side sibling of the machinery join, healing the same fragmentation one layer down (see `WATCHLIST.md`).
* **Idle-vs-focused split:** `IDLE_SPLIT_MS` (5 min, capture-time — a focused-but-idle tab renders as absence).
* **Visit/thread-return evidence (`VISIT_GAP_MS`, 5 min):** does three independent jobs sharing one value — LOW-band absence-bridge merging (noise-tolerance), raw-fragment container-return chaining (intent-credit), and title-run splitting (labeling). Not one shared code path; three separate call sites that happen to agree. Candidate for splitting into per-purpose names if any one of the three ever needs to move independently (see `WATCHLIST.md`).
* **Assembled-object bridging:** `CONTAINER_CHAIN_GAP_MS` (10 min, second-pass container-of-containers chaining) — deliberately looser than `VISIT_GAP_MS` because a chained container is a coarser claim than a raw fragment.
* **Departure/"walked away" evidence (30 min):** `AUDIO_BOOKEND_GAP_MS` (container gap-audio bridge — the tab's own audio testifies, and since 2026-08-24 only across an unchanged URL: the audio proves the TAB kept playing, not that the same ACTIVITY continued) and `FENCE_BRIDGE_GAP_MS` (away-plate gate ONLY as of 2026-08-08, below — a wall-clock judgment about leaving the machine) currently agree at 30 min but are **two independently-defined constants, not one** — the code deliberately keeps them separate (different evidence: one is a fact about the tab, the other a fact about the user), and nothing enforces they stay equal. Retuning one without the other is a legitimate design choice, not a bug, but should be a deliberate one. `FENCE_BRIDGE_GAP_MS` gates ONLY the away plate — fencing was removed 2026-08-25 and the constant outlived it (a rename to `AWAY_PLATE_GAP_MS` is pending).
* **Terminal-action discount:** `TERMINAL_KEY_MS` (500ms — the close-chord keystroke that doesn't count as engagement).
* **Copy/cut floor (20s, seconds not ms — the one outlier unit in this family):** `COPY_CUT_FLOOR_ATTENDED_S` gates the copy/cut scoring discount.
